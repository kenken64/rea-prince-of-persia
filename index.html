GRAPHICS MEMORY

No separate graphics ROM.

This cartridge uses 8 KiB of CHR RAM. Graphics are stored alongside code in its program banks and copied into graphics memory.

$C008

Where it begins

The reset routine disables rendering, waits for two vertical-blank transitions, clears RAM, then calls the initialization routines. Rea recovered the 6502 instructions and decompiler output.

$EB3A

A world in pointers

Three fourteen-entry pointer tables locate room tiles, spawn and event headers, and room connections. A room contains 30 tile bytes arranged as ten columns and three rows.

$F21B

A room and a direction

The spawn routine reads the first header byte and subtracts one for its internal room index. It then reads the starting tile and facing direction from the same header.

Reconstruction notes & evidence +

Recovered: all 14 level streams, 271 present rooms, original room links, spawn records, raw guard records, 146 active events, original sprite layouts, background compositions, palette indices, and torch frames. The level streams round-trip to the original bytes exactly.

Reconstructed: the C engine, general physics, collision interpretation, combat, most animation timing, HUD icon pixels, and some dynamic display behavior. They are editable implementation choices and have not been validated as behaviorally equivalent to the original game.

Ledge correction: catch anchors, hanging poses, climb/lower frame sequences and their coordinate changes were recovered from the ROM. Controlled runs of the original game verified both climb directions and the four-frame cadence. The C catch tolerance and release collision branches remain adaptations. Ledge evidence.

Guard animation: guards use recovered stepping, attack, parry, hurt and death poses with their own animation clocks. Defeated guards remain visible. Exact combat timing and full enemy AI remain reconstructed. Guard evidence.

Still unresolved: exact movement and animation timing, enemy AI, some contextual/dynamic graphics, cutscenes, music/audio and level-specific scripts. The 14 recovered layouts do not establish an exact full-game port.

Technical references: NES 2.0 header, UxROM mapping, and the NESPrincEd author’s format investigation. Extraction verifies offsets and stream boundaries against the supplied ROM. Complete recovered level data.
