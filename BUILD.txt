PRINCE OF PERSIA / NES RECONSTRUCTION

This is an independent C gameplay reconstruction compiled to WebAssembly.
It uses level bytes, original sprite layouts, background compositions and palettes recovered from the supplied NES ROM.
It contains no NES CPU interpreter and does not execute the original ROM.

BUILD
1. Install/extract an official WebAssembly/wasi-sdk release for your computer.
   https://github.com/WebAssembly/wasi-sdk/releases
2. Set WASI_SDK_PATH to its directory.
3. Run npm run build, then npm run dev.
4. Open http://localhost:8000 in your browser.

No npm dependency installation is required.
Display profile crops 8 lines from the top and bottom of the native 240-line
image to show 256x224, as in a typical NES screenshot. This is a display choice.
HUD icon pixels are reconstructed at their recovered original PPU coordinates.
The original author's NES game source was not recovered. The C code is a new
implementation. Exact animation timing, enemy AI, level-specific scripts,
audio and some dynamic display behavior remain subject to further ROM analysis
and validation.

assets/native-metatiles.json  Original background layouts, masks and joins.
assets/palettes.json  Original palette indices, FCEUX RGB profile and torch frames.
assets/background-animations.json  Original gate, chomper and spike frame maps.
native-renderer.js  Native pixel composition and sprite display.
app.js             Canvas display, browser input, map/data inspection.

The parent project's analysis/rea directory contains saved Rea Evidence JSON.
tools/extract_levels.py, tools/extract_actor_frames.py,
tools/extract_palettes.py and tools/extract_native_metatiles.py --fidelity-v2
reproduce extraction from the SHA256-verified user-supplied ROM.

Controls: arrows / WASD move; Space jump; Shift or X action/attack;
Hold Shift/X to grab; while hanging, Up climbs and releasing Shift/X lets go.
Down at an exposed edge lowers the Prince; Down while hanging lets go.
Up also interacts; Down elsewhere crouches. R restart; P pause.
The original hanging swing is finite, so climb before it finishes.

LEDGE VALIDATION
ROM bytecode and controlled original-ROM execution establish the catch anchors,
pre-climb alignment, frame order (including skipped frame148), and +/-63 pixel
anchor transfers during climb/lower. Climb uses four 60Hz ticks per pose, as
observed in the original Level1 scenario. General jump/catch tolerance, release
branch selection and room-boundary transitions still use the independent C
collision model; this does not establish complete controller equivalence.

Original game, character and art remain the work of their respective authors.
